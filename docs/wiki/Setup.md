# Setup Guide

This guide covers the two supported ways to run CMS: the all-in-one Docker image, and local development of the Node.js service and web apps against an existing CMS backend.

---

## 1. Prerequisites

| Requirement | Notes |
|---|---|
| **Docker** | Recommended. The image bundles Node 24, .NET 10 ASP.NET runtime, Nginx, and ffmpeg. |
| **Node.js 20+** | Required for local development. Docker uses Node 24. |
| **npm 10+** | Workspaces are used throughout the monorepo. |
| **A CMS backend** | For local development: an ASP.NET Core CMS reachable at `CMS_BASE_URL` (default `http://127.0.0.1:5000`). The easiest option is to run the Docker image on port 5000 and develop the Node service against it. |

You do **not** need the .NET SDK to run the Docker image. You do need it only if you are building the image from source and must publish `CMS.MonoApp` yourself — and the .NET CMS source is not in this repository.

---

## 2. Option A — Run the Docker image (fastest)

```bash
docker run -d \
  --name cms \
  -p 5000:5000 \
  -v cms_data:/data \
  -e DATABASE_PROVIDER=0 \
  -e "CONNECTION_STRING=Data Source=/data/cms.db" \
  -e CMS_DATA_PATH=/data \
  -e "DATABASE_URL=file:/data/app/sqlite.db" \
  senthil455/cms-mono:latest
```

Open **http://localhost:5000/app/** and complete the setup wizard:

1. Confirm the database.
2. Create the Super Admin account.
3. Open **Settings → AI Providers** and save a Gemini or OpenAI API key.
4. Start a conversation in the Studio.

The trailing slash matters: Nginx matches `/app/`, `/admin/`, `/portal/`, `/stash/`, `/cmsapi/`, and `/static/` with a regex that requires the slash.

### Persistent data

| Path | Contents |
|---|---|
| `/data/config/cms.settings.json` | CMS database configuration generated by `entrypoint.sh` |
| `/data/app/sqlite.db` | Fastify/Prisma data: chat history, AI logs, settings, design styles, tasks |
| `/data/cms.db` | CMS database when `DATABASE_PROVIDER=0` (SQLite) |
| `/data/files/` | Uploaded CMS assets |

Mount `/data` as a volume to keep all of it. Without the volume, the container is ephemeral.

For PostgreSQL, multi-arch builds, and troubleshooting, see [Docker Deployment](./Docker-Deployment.md).

## 3. Option B — Local development

### 3.1 Clone and install

```bash
git clone https://github.com/Senthil455/CMS.git
cd CMS
npm install
```

### 3.2 Start a CMS backend

The local Studio calls the CMS directly for `/api`, `/graphql`, and `/files`, while calling the local Fastify service for `/cmsapi`. Point both at the same CMS.

The simplest approach is to run the Docker image from Option A on port `5000`. If you have the CMS source separately, start it so that it listens on `http://127.0.0.1:5000` and accepts the session cookie used by the Studio.

### 3.3 Configure the service

Create `packages/service/.env` if you need non-default values:

```dotenv
PORT=3001
CMS_BASE_URL=http://127.0.0.1:5000
FRONTEND_URL=http://localhost:5173
DATABASE_URL=file:./dev.db
SESSION_SECRET=replace-with-at-least-32-characters
```

All variables are validated with Zod at startup. A missing or invalid required value aborts the process. See [Configuration](#configuration) below.

### 3.4 Initialize the service database

```bash
npm run setup
```

This builds `@cms/shared`, generates the Prisma client, and pushes the SQLite schema into `packages/service/dev.db`.

### 3.5 Start the Studio and service

```bash
npm run dev
```

This runs, concurrently:

- `@cms/service` with `tsx watch` on **http://127.0.0.1:3001**
- `@cms/app` with Vite on **http://127.0.0.1:5173**

Open **http://127.0.0.1:5173/app/**.

> Use `127.0.0.1` consistently. Cookies are scoped per host, so mixing `localhost` and `127.0.0.1` produces confusing login failures.

### 3.6 Run the other apps

```bash
npm run dev:admin      # http://127.0.0.1:5173/admin/
npm run dev:portal     # http://127.0.0.1:5173/portal/
npm run dev:stash      # http://127.0.0.1:5176/stash/
```

Admin and Portal have **no dev proxy of their own**. They are designed to be served by the Fastify service at `/admin/` and `/portal/`, or to talk to an origin configured through `VITE_REACT_APP_API_URL`. Do not run several Vite apps on the same port at once.

Stash has its own proxy and runs on port `5176`:

| Prefix | Target |
|---|---|
| `/api`, `/graphql`, `/files` | `http://127.0.0.1:5000` |
| `/cmsapi` (incl. WebSocket) | `http://127.0.0.1:3001` |

The Studio proxy is similar, and also forwards `/admin` and `/portal` to the Node service.

## 4. Configuration

The Node service reads environment variables through `packages/service/src/config.ts` and `dotenv/config`.

| Variable | Default | Purpose |
|---|---|---|
| `PORT` | `3001` | Fastify listen port |
| `NODE_ENV` | `development` | `development`, `production`, or `test` |
| `DATABASE_URL` | `file:./dev.db` | Prisma SQLite database for service-owned data |
| `CMS_BASE_URL` | `http://127.0.0.1:5000` | Upstream CMS for API calls and proxying |
| `CMS_PUBLIC_URL` | `http://127.0.0.1:5000` | Public CMS origin (reserved; not used by the browser SDK today) |
| `FRONTEND_URL` | `http://localhost:5173` | Allowed CORS and Socket.IO origin |
| `SESSION_SECRET` | development fallback | Session signing secret, minimum 32 characters |
| `SESSION_COOKIE_NAME` | `session` | Service session cookie name |
| `SESSION_MAX_AGE` | `86400000` | Session lifetime in milliseconds |
| `GEMINI_API_URL` | `https://generativelanguage.googleapis.com` | Gemini API base URL |
| `GEMINI_USE_CACHING` | `false` | Enable Gemini context caching |
| `OPENAI_API_URL` | `https://api.openai.com/v1` | OpenAI API base URL |
| `LOG_LEVEL_FASTIFY` | `warn` | Fastify/Pino log level |
| `LOG_LEVEL_SERVICE` | `info` | Service logger level |
| `LOG_LEVEL_MODEL` | `info` | Model/agent logger level |
| `LOG_LEVEL_INFRASTRUCTURE` | `info` | Infrastructure logger level |

### AI keys are not environment variables

Gemini and OpenAI keys are stored in the service database under `SystemSetting` (`GEMINI_API_KEY`, `OPENAI_API_KEY`) and managed from **Settings → AI Providers**. They are currently persisted as plaintext.

### Docker-only CMS variables

These configure the bundled ASP.NET Core CMS and Nginx:

| Variable | Default | Purpose |
|---|---|---|
| `DATABASE_PROVIDER` | `0` in `entrypoint.sh`; `1` in Compose | `0`=SQLite, `1`=PostgreSQL, `2`=SQL Server, `3`=MySQL |
| `CONNECTION_STRING` | `Data Source=cms.db` | ADO.NET connection string |
| `CMS_DATA_PATH` | unset (uses `/app/cms/cms.settings.json`) | Directory that receives `config/cms.settings.json` |
| `CMS_MAX_REQUEST_SIZE` | `50000000` | Nginx `client_max_body_size` in bytes |
| `MASTER_PASSWORD` | empty | Optional CMS setup password; normally set through the UI |

## 5. Database initialization

The service owns five Prisma models in `packages/service/prisma/schema.prisma`:

| Model | Purpose |
|---|---|
| `ChatMessage` | Chat history per CMS user ID |
| `AiResponseLog` | Prompt, response, model selection, and schema ID for replay |
| `SystemSetting` | Key/value settings, including AI API keys |
| `DesignStyle` | Named list/detail prompt presets |
| `AgentTask` | JSON-encoded task items and status |

`sessions.db` is created separately by `better-sqlite3` in the process working directory and is **not** managed by Prisma.

```bash
npm run setup      # shared build + prisma generate + prisma db push
```

To reset local service data, stop the service and delete `packages/service/dev.db` and `packages/service/sessions.db`, then rerun `npm run setup`. This does not touch CMS content, which lives in the ASP.NET Core database.

## 6. Build commands

```bash
npm run build:shared                 # @cms/shared → dist
npm run build:app                    # Studio
npm run build:stash                  # Stash PWA
npm run build --workspace=@cms/admin
npm run build --workspace=@cms/portal
npm run build:all                    # every workspace that defines a build script
```

Important details:

- `@cms/sdk` has **no build script**. It is consumed directly from TypeScript source via its `main`/`types` fields. `npm run build:sdk` is defined at the root but fails because the workspace exposes no `build` script.
- `npm run build:all` uses `--if-present`, so it skips `@cms/sdk`.
- The Fastify service is run with `tsx` in the Docker image after `prisma db push`; a `tsc` build exists but the entrypoint uses source execution.

## 7. Troubleshooting

### `Unauthorized` on every `/cmsapi` request

The service validates the CMS session cookie. Confirm that:

1. The CMS is running at `CMS_BASE_URL`.
2. You are logged in through the CMS origin.
3. You use the same host (`127.0.0.1` or `localhost`) for the Studio and the CMS.

### Login appears to succeed, then immediately fails

Mixing `localhost` and `127.0.0.1` creates two cookie jars. Use one host everywhere. The Studio's Vite proxy points at `127.0.0.1` by default.

### Prisma errors on startup or `no such table`

Run `npm run setup`. In Docker, `entrypoint.sh` already runs `npx prisma db push --accept-data-loss` on every start.

### `EADDRINUSE` on port 3001 or 5173

Stop the previous process. `npm run dev` starts two processes; Ctrl+C should stop both, but orphaned `tsx`/`vite` processes can survive. Restart the terminal or kill the process using the port.

### AI provider list is empty

No key is configured. Open **Settings → AI Providers** and save a Gemini or OpenAI key. `GET /cmsapi/ai/providers` returns only model combinations for providers that have a stored key.

### Admin or Portal shows a blank page in dev

They do not proxy API calls on their own. Run them through the Fastify service (`http://127.0.0.1:3001/admin/`, `/portal/`) after building, or configure the API origin the app expects. Production uses the `/admin/` and `/portal/` paths served by Fastify.

### Socket.IO does not connect

Use the same origin and cookie. The socket path is `/cmsapi/socket.io`, and `FRONTEND_URL` must match the browser origin (the allowlist also swaps `localhost` and `127.0.0.1`).

### Docker build fails with `CMS/... not found`

The build context and Dockerfile expect a sibling `CMS` directory checkout and a `CMS/publish` folder. See [Docker Deployment](./Docker-Deployment.md#building-from-source).
